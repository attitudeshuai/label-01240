# 个人博客系统开发需求

## 项目概述
开发一个基于B/S架构的个人博客系统，采用前后端分离模式。前端使用Vue3，后端使用Spring Boot，数据库使用MySQL。

## 技术栈要求
- **前端**: Vue3 + Vite + Node.js v22.20.0
- **后端**: Spring Boot 3.5.6 + Java JDK 24 + Maven 3.9.11 + MyBatis
- **数据库**: MySQL
- **开发工具**: IntelliJ IDEA, VSCode, Apifox, DataGrip

## 核心功能模块

### 1. 用户认证模块 (AUTH)
- **用户注册**: 用户名唯一性验证、密码复杂度检查
- **用户登录**: 身份验证、会话管理
- **用户登出**: 安全退出、会话销毁

### 2. 博客文章模块 (BLOG)
- **博客发布**: 富文本编辑器支持(加粗、斜体、图片插入)、标题/标签设置
- **博客编辑**: 作者权限验证、内容更新
- **博客删除**: 软删除机制、确认对话框

### 3. 评论与互动模块 (INTERACT)
- **发表评论**: 纯文本评论、内容合法性验证
- **点赞功能**: 单用户单博客只能点赞一次、实时计数更新

### 4. 个人中心模块 (PROFILE)
- **个人主页**: 用户信息展示、统计数据(文章数、点赞数)
- **博客管理**: 个人博客列表、编辑删除操作、批量处理

### 5. 后台管理模块 (ADMIN)
- **用户管理**: 用户列表查看、禁用/启用账户
- **内容管理**: 全站内容审核、违规内容处理

## 非功能需求

**核心功能实现：**

1. **用户认证模块** (`backend/src/main/java/com/blog/controller/AuthController.java`)
   - 用户注册：用户名唯一性验证、密码复杂度检查（8-20位，包含字母和数字）
   - 用户登录：JWT Token 认证，24小时有效期
   - 用户登出：客户端删除 Token

2. **博客文章模块** (`backend/src/main/java/com/blog/controller/BlogController.java`)
   - 博客发布：WangEditor 富文本编辑器，支持加粗、斜体、图片插入
   - 博客编辑：作者权限验证
   - 博客删除：软删除机制（deleted_at 字段）

3. **评论与互动模块**
   - 发表评论：纯文本评论，内容长度限制
   - 点赞功能：唯一约束保证单用户单博客只能点赞一次

4. **个人中心模块**
   - 个人主页：用户信息、统计数据（文章数、获赞数）
   - 博客管理：个人博客列表、编辑删除操作

5. **后台管理模块** (`backend/src/main/java/com/blog/controller/AdminController.java`)
   - 用户管理：用户列表、禁用/启用账户
   - 内容管理：全站博客审核、下架/上架

6. **安全设计**
   - 密码使用 BCrypt 加密存储
   - JWT Token 认证机制
   - 接口级别权限验证
   - 操作日志记录

7. **数据库设计** (`backend/src/main/resources/schema.sql`)
   - user: 用户表
   - user_profile: 用户资料表
   - blog: 博客表（含软删除字段）
   - comment: 评论表
   - blog_like: 点赞表（唯一约束）
   - operation_log: 操作日志表

**User**

未登录时打开首页显示网络错误

---

**Cursor**

问题原因：服务启动顺序问题。后端 Spring Boot 应用启动需要时间，但前端 nginx 已经开始接收请求，导致代理到后端时连接被拒绝（502 错误）。

**修复方案：**

1. 修改 `backend/Dockerfile`，安装 curl 用于健康检查：
```dockerfile
RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*
```

2. 修改 `docker-compose.yml`，为后端添加健康检查，并让前端等待后端健康后再启动：
```yaml
backend:
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:8080/api/blogs"]
    interval: 10s
    timeout: 5s
    retries: 10
    start_period: 30s

frontend:
  depends_on:
    backend:
      condition: service_healthy
```

**重新部署命令：**
```bash
docker-compose down
docker-compose up --build -d
```

现在前端会等待后端完全启动并通过健康检查后才启动，避免了未登录时首页显示网络错误的问题。
